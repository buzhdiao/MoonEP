## 全仓导读：MoonEP 是什么

MoonEP 是一个专家并行（Expert Parallelism）通信库，核心思想是**动态冗余专家驱动的完美负载均衡**：允许专家被多个进程同时持有副本，由在线规划器把每个进程的接收量强制钳位到定值（每进程 S 乘 K 个路由项），从而让通信、计算、显存与调度全部免疫路由偏斜。它的三个设计支柱——完美均衡、设备内在线规划、零拷贝与静态形状——分别由规划子系统、数据面子系统与缓冲子系统实现，三者咬合成闭环（第一章第五节）。

仓库的语言形态：Python 编排层（moonep/api.py 等三个文件）、CuTe DSL 设备内核层（九个文件）、CUDA 驱动适配层（csrc/ 两个文件）；测试体系（moonep/tests/ 十一个文件）与基准体系（benchmarks/ 四个脚本）构成质量与性能的守护面。全仓库约一万五千行代码，公开接口只有两个符号（Buffer 与 MoonEPCommPlan）与四个通信算子（dispatch、prefetch_weight、combine、reduce_grad）。

## 各章摘要

**第一章 专家并行通信问题与 MoonEP 定位**。建立全书的记号体系（S、K、E、R、epn、N、N v）与问题刻画：专家并行的接收量随路由分布波动，同时污染通信（热进程木桶）、计算（GEMM 失衡）、显存（动态形状碎片化）与调度（每层宿主同步）。给出 MoonEP 的回答——动态冗余专家：用受控的重复把接收量钳位到定值——并论证均衡目标的可达性、冗余预算的合理性，以及完美均衡、在线规划、零拷贝三支柱的递进关系。附一个两进程八专家的数值例子贯穿全书。

**第二章 总体架构与分层设计**。三层结构（Python 编排、CuTe DSL 内核、CUDA 驱动适配）的职责与单向依赖；以预分配上下文为基础的静态形状体系；通信计划对象作为四次算子调用之间的中心契约（一次训练迭代被消费五次）；流与事件的重叠模型、程序化依赖启动、跨进程对齐内核；编译期特化与缓存的内核工程风格；生命周期与资源安全（显式销毁、析构告警、测试兜底）。

**第三章 规划系统（上）：问题建模与算法原理**。把规划形式化为带结构性约束（每进程至多收一个远端归属组）的整数再指派问题；专家整只搬迁是自由度原子，贪心加前缀和是构造手段；目的地表的符号编码（非负为真实槽位、负值为主项编码）与来源表支撑去重；静态槽位容量的闭式上界（填充粒度减一乘两倍每卡专家数）；设备内规划的时延论证；三张前缀和表的分工、复杂度分析、计划时效性与复用边界。

**第四章 规划系统（下）：内核实现与正确性验证**。PlanningKernel 的单次协同启动四阶段（计数汇总、零号进程决策与组播发布、稳定重排 run_c1、逐项求目的地与写回）；三重计数排序的并行化与确定性设计；组播广播、异步代理一致性、共享内存静态规划；参考实现（moonep/tests/planning_reference.py）与不变量体系（配额、编码一致性、语义对齐、确定性锚点）构成的双层验证。

**第五章 分发全链路**。DispatchKernel 的线程束分工（装载、写出、清零、去重构建四类束）；整行直写远端最终位置（融合重排）；路由权重散布与选择序恢复；填充清零的正确性与确定性论证；去重结构的两轮构建（原子序不确定性及其测试处置）；收尾跨进程发布屏障；分发尾声的原位重复展开；缓冲区读写归属契约；与基准算子的对应。

**第六章 汇合全链路**。汇合作为散射的伴随：前置内核在本地归并重复行（单精度寄存器、设备端计数、轮转分派），主内核以三级流水线（装载、四累加束、写出）跨卡拉回去重主行并按选择累加；装载级数的自动挑选与数值演算；入口发布屏障与预对齐的分工；零拷贝的完整生命周期契约；反向复用（汇合的逆是按原计划重发、分发的逆是一次汇合）与数值性质。

**第七章 梯度归约**。属主拉取语义（与预取的推送对偶）；归约缓冲与紧凑梯度视图的布局；持久分块归约内核（一百二十八乘一百二十八分块、五线程束、播种与延迟隐藏）；预扫描压缩活跃专家表（协作式三段式）；寄存器累加器与静态步长的教训；本地清零战胜远程清零的互连带宽方向账；升序累加的确定性承诺；与框架参数梯度归约的解耦。

**第八章 权重预取与 MXFP4**。属主推送模型与任务表压缩；持久多张量单启动（三投影加三缩放因子共享一次发射、编译期张量循环、每张量独立二维描述符）；分块几何与缩放因子重铺；MXFP4 打包格式（每字节两个四比特值）与第八位缩放因子；生产规模的六十四位寻址（越界偏移的测试边界）；完成屏障与重叠时序；组播写的三个使用者与适用判据。

**第九章 缓冲区管理与内存布局**。虚拟内存管理三原语（创建、凭据、映射）；两种凭据路线（节点内描述符经套接字传递、跨节点织物句柄六十四字节）与自动选择；全组连续虚拟地址与仿射寻址；组播对象五步生命周期与失败路径；元数据缓冲八分区布局（权重、计数、规划输出、三段暂存、屏障、来源）与四条布局纪律；预取池与归约池的进程全局共享；生命周期时序与三道防御；两层视图模型（虚拟与物理）。

**第十章 内核工程与通信原语**。CuTe DSL 的选型权衡；批量拷贝的两个方言缺陷及内联汇编绕行（单维盒上限、地址空间修饰错配）与单通道发射纪律；两级流水线与级数自动化；软件全栅栏的自复位哨兵设计（最高位翻转协议）；跨进程屏障的三整数相位协议与内存序配对；同步设施全家福与选型决策树；线程束级原语（匹配、位计数、扫描、平局裁决极值）；原子作用域纪律；程序化依赖启动的触发等待语义；寄存器驻留的编译器行为边界。

**第十一章 API 契约、校验与测试体系**。校验哲学（错误拦在设备之前）与三层校验分布；四算子形状契约表；环境变量配置面；测试基建（多进程启动器、自动清理、会话夹具）；用例描述语言与参数化；全秩断言家族与四级数值断言；路由生成器的对数正态偏斜建模与种子分层；不变量与语义比较器；六文件覆盖轴矩阵；基准脚本作为活的规格说明。

**第十二章 同类系统对比、性能模型与总结展望**。与 DeepEP 第二代弹性路径的机制对比表；公平对比协议与结果解读；性能字节账（数据面流量恒定、次级流量受预算钳制、控制面占比演进）；容量与显存账；已知限制（组规模、路由项总数、整除性、互连域、组播依赖）；被实测验证的决策复盘；开放问题结构化清单；给后来系统的四条设计原则。

**第十三章 专题：调优实践与故障诊断**。调优参数总览与"先基准后调参"策略；重叠编排三规则；量化专家接入清单；症状三分类诊断（挂死、错值、报错）与分步脚本；剖析归因三步法；偏斜度巡检（远端统计量作为模型健康探针）；数值调试五件工具；标准化报告模板；回归节律；诊断案例与读码路线。

## 十个最常见的问题（快速索引）

以问答形式给出阅读前的十个高频问题，每问标注答案所在章节，兼作检索入口。

第一问：MoonEP 与直接用 DeepEP 的区别是什么？答：机制上，MoonEP 用动态冗余专家把每进程接收量钳位到定值，通信与计算不再随路由偏斜恶化；接口上与生态兼容。见第一章第四节、第十二章第二节。第二问：均衡会不会增加计算量？答：不会——每个路由项仍只在一个副本上计算，总计算量不变，改变的只是位置；显存增加的是进程全局共享的预取池（每卡每投影每卡专家数个专家，与层数无关）。见第一章第四节、第九章第七节。第三问：规划为什么能塞进关键路径？答：它是纯元数据引擎，数据量与专家数同阶、算术量与前缀和同阶，且全部在设备上单内核完成，基准里可单独计时且占比极小。见第三章第七节、第三章第十节、第四章。第四问：静态形状是靠什么保证的？答：规划的结构性约束（每进程至多收一个远端归属组）给出槽位上界的闭式推导，配合填充对齐得到固定容量；约束被测试的不变量体系守护。见第三章第三节、第三章第六节、第四章第九节。第五问：零拷贝什么时候能用？答：激活只被消费一次且不进自动微分计算图时（典型是推理或手工管理的流水线）；需要框架暂存激活时用非零拷贝。见第六章第十一节。第六问：量化专家要改通信库吗？答：不用——预取按字节搬运，四比特打包与缩放因子经视图重铺走同一条通道；格式契约由接口校验守护。见第八章第五节、第八章第十一节。第七问：训练梯度怎么闭合？答：副本梯度落在归约池，属主拉取累加（升序确定、本地清零），与框架的参数梯度归约解耦。见第七章。第八问：可以跨节点吗？答：当前版本面向同一互连域（织物句柄与组播的前提）；跨节点是开放问题清单的第一行。见第十二章第七节、第十二章第二十二节。第九问：怎么验证我集成对了？答：跑测试体系（分层的覆盖轴矩阵）加基准分段计时，第十三章第十节的检查单逐项核对。见第十一章、第十三章。第十问：想改内核从哪里入手？答：第十三章第十一节的读码路线加第十一章的测试样板；改契约先改文档字符串与参考实现。见第四章第八节。

仓库已有两份入门文档：README（英文）与 README_zh（中文），它们以特性与用法为主线，篇幅精炼。本卷与其关系是互补而非替代：README 回答"是什么、怎么用"，本卷回答"为什么这样设计、机制如何运作"。两者的术语体系一致（本卷第一章第七节的记号表与 README 的 Notation 一一对应），读者在两份文档间切换不需要重新建立词汇。本卷引用 README 的性能图与结论时均注明出处；README 未展开的机制细节（编码、协议、布局、测试）全部由本卷补全。若读者只有十分钟，建议先读 README 的特性清单再读本卷第一章第六节的系统栈图——这个组合给出最小的完整心智模型。若还有额外的一小时，把第一章第一至四节补上——问题刻画是一切机制讨论的公共前提，缺了它，后续每一章的"为什么"都要多问一遍。以上即本卷的全部导航信息——祝阅读顺利。本卷从调研到成文遵循同一条规则：每个断言必须能指回仓库中的某一行代码或某一条注释；若读者在阅读中发现无法对应的表述，那正是本卷希望收到的反馈。

## 如何引用本卷

学术引用请引用仓库本身（README 的引用条目）；本卷用于内部培训、集成评审与代码评审的上下文补充时，建议按"章号加机制名"的方式引用（例如"见原理介绍第四章第九节的不变量体系"），不要引用行号——本卷的章节结构稳定而行号无意义。引用性能结论时必须连同其证据层级（机制推演、基准实证、生态定位）一起引用（第十二章第二十八节的分层说明），这是本卷对读者的最后一条写作纪律要求。

## 阅读时需要的前置知识

本卷假定读者具备四方面的前置基础，并说明缺项的补法。其一，Transformer 与混合专家模型的基本结构：注意力的多头形态、前馈网络、路由与 top-k 选择的语义——缺项可读第一章第一节的算术刻画与仓库附带的参考模型。其二，数据并行与模型并行的基本形态：all-reduce 与 all-to-all 的区别、切分维度与通信量的关系——缺项可读第一章第一、二节，本卷对通信形态的刻画是自足的。其三，CUDA 的执行模型：流、事件、线程块与流多处理器的对应——缺项可读第二章第四节与第十章第一节，本卷在用到执行模型概念处均有就地解释。其四，基本的并发概念：原子操作、内存序、屏障——缺项可读第十章第五、八节，本卷对释放获取语义的用法有完整的推导。四项前置都不要求深入：本卷的写作目标是让具备任一子系统的经验、但对其他子系统陌生的读者也能通读——跨子系统的术语在首次出现处均有定义，术语表（上文）可随时回查。若某项前置确实为零，建议先读对应章节的"机制动机"段落（每章第一节）再决定是否补课——本卷的多数推理在动机层面是自足的，只有细节展开才依赖前置。
